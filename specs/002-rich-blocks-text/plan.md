# Implementation Plan: Новые блоки и оформление текста

**Branch**: `002-rich-blocks-text` | **Date**: 2026-10-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-rich-blocks-text/spec.md`

## Summary

Тринадцать новых блоков, цвет текста и фона, упоминания страниц, даты и напоминания; всё с синхронизацией, выгрузкой и импортом.
Подход сохраняет главное решение первой версии: страница — один текст на TextKit 2, абзац = блок (001 R2).
- Вложенность в переключатель, выноску и цитату — тот же отступ `indent`, что у списков: дети — следующие блоки глубже. Свёрнутый переключатель прячет абзацы детей от раскладки, сам текст не меняется (R1).
- Блоки без текста (картинка, файл, видео, закладка, формула, оглавление, разделитель, таблица, колонки) — абзац из одного знака-вложения, в котором живёт свой вид; вид создаётся, только когда блок виден на экране (R2).
- Колонки и таблицы живут вне общего текста: блок получает поле `containerId`. Колонка — свой редактор того же устройства; таблица рисует ячейки сама и даёт одно поле правки на активную ячейку (R3).
- Файлы — копия в папке приложения; на сервер уходят частями по 8 МБ, каждая зашифрована; сервер получает хранилище файлов (R9–R10).

## Technical Context

**Language/Version**: Swift 6.3 (приложение); TypeScript на Node.js 22 (сервер) — без изменений

**Primary Dependencies**: Как в 001: SwiftUI, AppKit (TextKit 2), CryptoKit, GRDB 7. Новые системные: UserNotifications (напоминания), AVKit (видеофайлы), WebKit (YouTube и Vimeo — только по нажатию «Играть»), ImageIO (уменьшенные картинки). Новая сторонняя одна: SwiftMath (формулы, MIT), исходниками в наш модуль с одним шрифтом (R6). Подсветка кода — свой разборщик (R5).

**Storage**: SQLite, миграция v6 с копией базы (data-model.md); файлы — `~/Library/Application Support/MyNotion/Attachments/`. На сервере — зашифрованные части в `/data/files`, учёт в той же SQLite.

**Testing**: Swift Testing (модули), XCUITest в виртуальном Mac (`scripts/vm/run-in-vm.sh`), Vitest (сервер)

**Target Platform**: macOS 26+, только Apple Silicon; сервер — прежний Docker на индонезийском сервере (`mynotion.kurilov.cloud`)

**Project Type**: desktop-app + маленький web-service (тот же, что в 001)

**Performance Goals**: набор ≤ 50 мс p95 на странице 1 000 блоков со всеми новыми типами (SC-102); подсветка блока кода 500 строк ≤ 50 мс p95 (SC-103); напоминание ≤ 1 мин после срока (SC-104); запуск ≤ 1 с, память в покое ≤ 200 МБ (сейчас 0,36–0,48 с и 46 МБ)

**Constraints**: файл ≤ 100 МБ; виды блоков и веб-проигрыватель не создаются вне экрана; при запуске до готовности редактора — ни одной новой работы; работа без интернета (видео YouTube и обновление закладки — с интернетом)

**Scale/Scope**: один пользователь, 2–3 Mac; эталон 001 (1 000 страниц, 100 000 блоков) плюс эталонная «богатая» страница на 1 000 блоков (quickstart.md); 6 историй P1–P6

Неясностей не осталось — решения в [research.md](research.md).
Одно ограничение вынесено Юрию на решение (R14): выгрузка Notion «Markdown & CSV» не содержит цветов и колонок, поэтому их импорт из неё невозможен.

**Structure Decision**: Тяжёлое (формулы, видео, веб, подсветка, файлы, напоминания) — отдельные модули с тонким интерфейсом; редактор знает их через протоколы фабрик видов, которые передаёт `App/`. Ядро получает только данные. Каждый новый тип блока — свой файл в `PageEditor/BlockKinds/`: параллельные этапы добавляют файлы, а не правят общие `switch`.

## Этапы (вертикальные срезы)

Темп взят по 001: этап с новым блоком, тестами и галереей — 1,5–3 ч работы агента.
Каждый этап — блок целиком: редактор, синхронизация, отмена, выгрузка, импорт, галерея, замер.

| № | Этап | Зависит от | Параллельно с | Оценка |
|---|------|------------|---------------|--------|
| 0 | **Фундамент**: миграция v6 и тест восстановления; поля блока и потоки в `PageDocument`; формат пачки v2; реестр типов `BlockKinds`; знак-вложение с видом по видимости; проба TextKit 2 (скрытие абзацев, код 500 строк в одном абзаце, вид-вложение) с замерами | — | S | 2–2,5 ч |
| S | **Сервер файлов**: `files.ts`, квота, корзина 30 дней, копии, тесты Vitest, развёртывание | — | 0, 1–3 | 1,5 ч |
| 1 | **US1** переключатель, цитата, выноска, разделитель; вложенность Tab; свёртывание; поиск разворачивает | 0 | 2, 3 | 2,5 ч |
| 2 | **US2** цвета в строке и у блока, палитра, тёмная тема | 0 | 1, 3 | 1,5 ч |
| 3 | **US3** упоминания «@» и «[[», даты, напоминания | 0 | 1, 2 | 2,5 ч |
| 4 | **US4** код с подсветкой, формулы (блок и строка), оглавление | 1 | 5, 6 | 2,5 ч |
| 5 | **US5** вложения: хранилище, отправка и докачка; картинка, файл, видео, закладка | 0, S | 4, 6 | 3 ч |
| 6 | **US6** таблица; колонки; ⌘F по всей странице | 1 | 4, 5 | 4 ч |
| 7 | Круговая проверка «выгрузка → импорт» всех блоков (SC-105), живой импорт из Notion (SC-106), полный прогон тестов, замеры, сверка галереи с Notion, сборка Release | все | — | 2–2,5 ч |

Волны: **A** — 0 ∥ S (≈ 2,5 ч); **B** — 1 ∥ 2 ∥ 3 (≈ 2,5 ч); **C** — 4 ∥ 5 ∥ 6 (≈ 4 ч); **D** — 7 (≈ 2,5 ч).
Итого ≈ 11–12 ч работы агентов по часам; сумма этапов без параллельности ≈ 21 ч.
Параллельные этапы — каждый в своём `git worktree`, не больше трёх агентов; вливание по одному, с затронутыми тестами после каждого.
Общие точки столкновений (меню «/», выгрузка, импорт, галерея) разведены в этапе 0 реестром «файл на тип блока».

Проверка интерфейса — как в 001: галерея состояний `--ui-gallery` в виртуальном Mac, сверка отдельным проверяющим с живым Notion и contracts/blocks-and-keys.md.
Цифры палитры и размеров в contracts/blocks-and-keys.md предварительные; этап, вводящий блок, снимает их с настоящего Notion (FR-119).

## Complexity Tracking

| Отступление | Зачем | Почему проще не подходит |
|-------------|-------|--------------------------|
| Два способа вложенности: отступ (переключатель, выноска, цитата) и `containerId` (колонки, таблицы) | Внутри общего текста вложенность по отступу сохраняет одно выделение и одну отмену через блоки (001 R2) | Колонки и ячейки стоят рядом по горизонтали — один текст TextKit так не раскладывается. Перевод всего на дерево `parentId` переписал бы редактор и синхронизацию 001 (R1, R3) |
| Несколько редакторов на странице (по одному на колонку) | Полноценные блоки внутри колонки: списки, переключатели, код | Рисованные колонки без редактора не дают правки; одна таблица-раскладка внутри TextKit недоступна (R3) |
| Новая зависимость SwiftMath (≈ 1,5 МБ с одним шрифтом) | Формулы LaTeX без веб-движка (FR-105) | Свой вёрстщик формул — тысячи строк правил TeX; KaTeX в WebKit — 40–80 МБ памяти и сотни мс на первый показ (R6) |
| WebKit для YouTube и Vimeo | Их проигрыватель есть только веб-страницей (FR-108) | Своего способа показать YouTube нет. Вид создаётся по нажатию «Играть» и закрывается вне экрана; в покое памяти не занимает (R8). Исключение по конституции: память во время игры видео может превысить 200 МБ — это не «покой», цифра снимается замером и показывается Юрию |
| Сервер хранит файлы | Решение Юрия 19.10.2026: файлы через наш сервер, 100 МБ | Без сервера картинки не попадут на второй Mac; iCloud отвергнут ещё в 001 |
