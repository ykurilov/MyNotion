# Quickstart: проверка ядра MyNotion

Как убедиться, что первая версия работает. Детали — в [contracts/](contracts/) и [data-model.md](data-model.md).

## Подготовка

- Mac на macOS 26, Xcode 26, XcodeGen; для сервера — Node.js 22 и pnpm.
- `xcodegen generate` в корне → `MyNotion.xcodeproj`.
- Сервер локально: `cd server && pnpm install && pnpm dev` → `http://localhost:8787/health` отвечает `ok`.

## Проверки по историям

| История | Команда | Ожидание |
|---------|---------|----------|
| Все модули | `xcodebuild test -scheme MyNotion` | все тесты зелёные |
| US1 сохранение | XCUITest `NoteSurvivesRelaunchTests` | текст совпадает после перезапуска и после принудительного завершения (потеря ≤ 1 с) |
| US2 дерево | XCUITest `PageTreeTests` | дерево из 3 уровней, перенос ветки, корзина и возврат переживают перезапуск |
| US3 блоки | XCUITest `BlockEditingTests` | все быстрые символы, меню «/», чекбокс, перестановка, ⌘Z/⇧⌘Z |
| US4 поиск | XCUITest `PageSearchTests` | на 1 000 страниц слово находит нужную, Enter открывает |
| US5 синхронизация | `pnpm test` в `server/` + `SyncConvergenceTests` | два клиента с локальным сервером: правка доходит, правки без связи сливаются, конфликт текста создаёт выбор, 0 потерь |
| US6 импорт | `NotionImportTests` на образце выгрузки в `Tests/Fixtures/notion-export/` | дерево и текст совпадают, отчёт перечисляет упрощённое |

### Замер 18.10.2026 (после синхронизации, поиска, импорта, панели форматирования и окна эмодзи)

Сборка Release, эталонная база, **виртуальный Mac** на Mac Studio M4 Max (`scripts/vm/run-in-vm.sh uitest --release`,
`scripts/vm/sync-memory-check.sh`). Процессор в виртуальном Mac почти как у хозяина, а графика медленнее: всё, что
рисует окно (переход между страницами, прокрутка), здесь медленнее, чем на самом Mac.

| Показатель | Предел | Факт |
|------------|--------|------|
| Запуск до готовности к вводу (страница на 1 000 блоков) | ≤ 1 с | 0,36–0,48 с (5 запусков) |
| Память в покое, синхронизация выключена | ≤ 200 МБ | 46 МБ |
| Память в покое, синхронизация включена | ≤ 200 МБ | 46 МБ (через 10 и 60 с); сразу после первой отправки всех 100 000 блоков — 173 МБ, отправка 6 с |
| Набор в странице на 1 000 блоков, p95 | ≤ 50 мс | 5,5–9,7 мс |
| Набор в странице на 10 000 блоков, p95 | ≤ 50 мс | 17–37 мс |
| Прокрутка страницы на 10 000 блоков, p95 | ≤ 50 мс | 3–16 мс |
| Открытие страницы на 10 000 блоков | — | 0,26–0,33 с |
| **Переход между страницами, p95** | ≤ 50 мс | **68–101 мс** (медиана ≈ 49 мс) — выше предела |
| Поиск, на символ, p95 | ≤ 100 мс | 16–23 мс (худшее 76 мс) |
| Импорт 1 000 страниц (147 400 блоков) | ≤ 60 с | 12,5 с; запись правки во время импорта p95 59 мс, худшая 100 мс |
| Выгрузка в Markdown 1 000 страниц | — | 9,1 с вместе с запуском |

Починено ради бюджета: после загрузки текста курсор стоял в конце страницы, и расчёт его места раскладывал всю страницу
(запуск был 0,87–1,26 с, открытие страницы на 10 000 блоков 3,9 с, переход медиана 82 мс).
Переход между страницами: из ≈ 49 мс медианы ≈ 12 мс — прокрутка дерева к далёкой строке (в замере страницы выбираются
вразброс; при щелчке в дереве строка уже видна), ≈ 18 мс — первая отрисовка, где виртуальный Mac ждёт графику.
Честный ответ, укладывается ли p95 в 50 мс, даст только замер Release на самом Mac.

## Живая проверка на двух Mac

1. Сервер развёрнут на `mynotion.kurilov.cloud` (скилл server-deploy), `/health` → 200.
2. Mac 1: Настройки → Синхронизация → подключить (токен первого устройства).
3. Mac 1: «Добавить Mac» → код. Mac 2: ввести код.
4. Правка на Mac 1 видна на Mac 2 не позже 10 с.
5. Отключить сеть на обоих, править один блок на обоих, вернуть сеть → появляется «Две версии», выбор расходится на оба Mac.
