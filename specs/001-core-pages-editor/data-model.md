# Data Model: Минимальное ядро MyNotion

**Date**: 2026-10-15 | **Spec**: [spec.md](spec.md) | **Research**: [research.md](research.md)

Хранилище на Mac — SQLite (R3). Все id — UUID v7: упорядочены по времени, уникальны между Mac.
Каждая изменяемая запись несёт гибридную метку времени (`HLC`, R8) по каждому синхронизируемому полю.

## Page — страница

| Поле | Тип | Правила |
|------|-----|---------|
| id | UUID | неизменен |
| title | текст | может быть пустым; показывается «Без названия» |
| icon | текст? | один эмодзи или пусто |
| parentId | UUID? | пусто — корень дерева; не может указывать на себя или потомка |
| sortKey | текст | дробный ключ порядка среди соседей (вставка между двумя без перенумерации) |
| trashedAt | время? | не пусто — страница в корзине вместе с потомками |
| createdAt, updatedAt | время | |
| fieldClocks | HLC по полям | title, icon, parentId+sortKey (одно поле «место»), trashedAt |

**Переходы состояния**: активна → в корзине (удаление, FR-005) → активна (возврат) или удалена навсегда (очистка корзины).
Удаление навсегда оставляет «надгробие» (id + HLC) для синхронизации; само содержимое стирается. Правка, сделанная без знания о стирании, возвращает страницу в корзину (research R8).

## Block — блок

| Поле | Тип | Правила |
|------|-----|---------|
| id | UUID | неизменен |
| pageId | UUID | страница-владелец |
| kind | перечисление | paragraph, heading1, heading2, heading3, bulletItem, numberedItem, checkbox, pageLink |
| text | текст с оформлением | см. «Оформление в строке» |
| indent | целое 0…8 | вложенность списков и чекбоксов (FR-008); для заголовков всегда 0 |
| isChecked | логический | только для checkbox |
| linkedPageId | UUID? | только для pageLink; указывает на подстраницу |
| sortKey | текст | порядок на странице |
| fieldClocks | HLC по полям | kind+indent, text, isChecked, sortKey, deleted |
| textBaseClock | HLC | версия текста, от которой началась правка; основа выявления конфликта (R8) |

**Правила**:
- У страницы всегда есть хотя бы один блок (пустой абзац).
- Подстраница создаётся парой: Page с `parentId` и блок `pageLink` в родителе (FR-002, сценарий 2.1).
- Удаление блока — пометка `deleted` с HLC, физически стирается после того, как все устройства получили изменение (то же для надгробий страниц). Пока Sync выключен, стирается сразу.

### Оформление в строке

Текст хранится строкой и списком отрезков: `[{start, length, style}]`, где style ∈ bold, italic, strikethrough, code, underline, link(url).
Это одно поле `text` для синхронизации: текст и его оформление меняются вместе.
Подчёркнутый (`underline`, FR-033) добавлен без миграции схемы: отрезки лежат JSON-списком в той же колонке `textStyles` (и в `localVersion`/`remoteVersion` конфликтов), новый стиль — просто новое слово в поле `style`. Старые версии приложения такое слово не прочтут (неизвестное оформление — ошибка разбора), поэтому базу с подчёркнутым текстом открывать только этой версией и новее.

### Перенос строки внутри блока (FR-032)

Shift+Enter переносит строку, блок остаётся одним. В `text.string` перенос — обычный `\n` (U+000A): так его понимают поиск, выгрузка в Markdown и импорт.
В редакторе страница — один `NSTextStorage`, где абзац = блок, поэтому там тот же перенос — разрыв строки U+2028: TextKit и `paragraphRange` не считают его границей абзаца.
Замена `\n` ⇄ U+2028 — только при переводе блока в текст страницы и обратно (`PageTextStorageMapper`). Оба знака длиной в одну единицу UTF-16, и отрезки оформления не сдвигаются.
Других разделителей абзацев (`\r`, U+2029) в `text.string` нет: вставка из других программ делит текст по строкам на отдельные блоки.

## Conflict — конфликт текста

| Поле | Тип | Правила |
|------|-----|---------|
| id | UUID | |
| blockId | UUID | спорный блок |
| localVersion, remoteVersion | текст с оформлением | обе версии целиком |
| remoteDeviceName | текст | с какого Mac пришла вторая версия |
| detectedAt | время | |
| resolvedAt | время? | пусто — ждёт выбора Юрия |

**Переходы**: ожидает → решён (выбрана одна версия, или обе оставлены двумя блоками подряд).
Пока конфликт ждёт, в блоке показана локальная версия с пометкой. Решение — обычное изменение текста с новым HLC, оно расходится на все Mac.

## TrashEntry — запись корзины

Отдельной таблицы нет: корзина — страницы с `trashedAt`, у которых родитель не в корзине.
Прежнее место хранится в `parentId` + `sortKey`, поэтому возврат ставит страницу туда же. Если родитель исчез — в корень.

## SearchIndex — поиск

Таблица FTS5 `(pageId, blockId, content)`, где для названия страницы `blockId` пуст.
rowid строки названия — `-page.rowid`, строки блока — `block.rowid`: правка находит свою строку без перебора, а названия отделяются от текста условием на rowid. «ё» записывается как «е»; пустые названия и блоки не индексируются. Схема v4 наполняет индекс для баз, созданных до поиска (перед миграцией — копия базы).
Обновляется в той же транзакции, что Page.title и Block.text: ядро даёт подписчикам хук «внутри транзакции записи», а не уведомление после неё. Страницы в корзине из выдачи исключаются.

## WindowState — состояние окна

| Поле | Тип |
|------|-----|
| windowId | UUID |
| openPageId | UUID? |
| collapsedPageIds | набор UUID |
| sidebarWidth | число |
| isSidebarCollapsed | да/нет — панель спрятана шторкой (схема v3) |

Локальное, не синхронизируется: у каждого Mac своё.

## Device и SyncState — синхронизация (модуль Sync)

| Сущность | Поля |
|----------|------|
| SyncAccount | serverURL, deviceId, deviceName, deviceToken (связка ключей), encryptionKey (связка ключей), lastPulledSeq |
| OutboxEntry | id, createdAt, payload (изменения полей с HLC), sentAt? |

- Любое изменение Page или Block в той же транзакции (через тот же хук ядра) кладёт запись в OutboxEntry — только если модуль Sync включён.
- Выключение синхронизации удаляет SyncAccount и очередь, записи не трогает (FR-024).

## ImportRun — импорт из Notion

| Поле | Тип |
|------|-----|
| id | UUID |
| sourceFingerprint | хеш содержимого выгрузки |
| startedAt, finishedAt? | время |
| rootPageId | UUID? |
| importedPages | целое |
| simplifiedItems | список «страница — что упрощено» |
| status | running, finished, failed |

Повторный импорт с тем же `sourceFingerprint` — предупреждение до начала (FR-027).

## Схема и миграции

- Версия схемы ведётся миграциями GRDB. Каждая миграция проверяется тестом «старая база → новая» на копии эталонной базы.
- Перед миграцией делается копия файла базы рядом (`MyNotion.backup-<версия>.sqlite`), восстановление из неё проверяется тестом (принцип IV).
