# Implementation Plan: Минимальное ядро MyNotion для macOS

**Branch**: `001-core-pages-editor` | **Date**: 2026-10-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-core-pages-editor/spec.md`

## Summary

Личное приложение заметок для macOS: дерево страниц, блоки текста, автосохранение, поиск страниц, синхронизация между Mac через сервер `mynotion.kurilov.cloud` и импорт из Notion.
Подход: нативное приложение на Swift (SwiftUI + AppKit), один текстовый движок Mac на страницу, записи в SQLite на каждом Mac.
Сервер синхронизации — маленький «почтовый ящик» зашифрованных изменений; правки сливает сам Mac.

## Technical Context

**Language/Version**: Swift 6.3 (приложение); TypeScript 5 на Node.js 22 (сервер синхронизации)

**Primary Dependencies**: Приложение — системные SwiftUI, AppKit (TextKit 2), CryptoKit, Security; сторонняя одна — GRDB.swift 7. Сервер — Hono, better-sqlite3.

**Storage**: SQLite (WAL) в `~/Library/Application Support/MyNotion/`; на сервере — SQLite в томе Docker.

**Testing**: Swift Testing (модули), XCUITest (сценарии и замеры), Vitest (сервер)

**Target Platform**: macOS 26+, только Apple Silicon; сервер — Ubuntu 24.04, Docker (индонезийский сервер)

**Project Type**: desktop-app + маленький web-service

**Performance Goals**: запуск ≤ 1 с; набор и переход ≤ 50 мс p95; поиск ≤ 100 мс на символ; синхронизация ≤ 10 с; импорт 1 000 страниц ≤ 60 с

**Constraints**: память ≤ 200 МБ в покое; полная работа без интернета; записи на сервере только в зашифрованном виде; потеря при сбое ≤ 1 с набора

**Scale/Scope**: один пользователь, 2–3 Mac; эталон 1 000 страниц и 100 000 блоков; 6 пользовательских историй

Неясностей не осталось — все решения в [research.md](research.md).

```text
    ├── MarkdownExport/        # выгрузка в папку Markdown
    ├── NotionImport/          # разбор выгрузки Notion
    └── Sync/                  # часы HLC, слияние, шифрование, клиент сервера
└── Tests/                     # по папке на модуль + Fixtures/ (образец выгрузки Notion, генератор эталонной базы)
UITests/                       # XCUITest: сценарии историй
PerformanceTests/              # замеры бюджета (Release)
server/                        # сервер синхронизации
├── package.json, pnpm-lock.yaml
├── src/                       # app.ts (маршруты), journal.ts (журнал и снимки), devices.ts (устройства и приглашения)
├── test/
├── Dockerfile
└── docker-compose.yml
```

**Structure Decision**: Логика живёт в модулях Swift-пакета с тонкими интерфейсами к `NotesCore`; приложение `App/` только собирает их в окна. Модули-добавки (`PageSearch`, `MarkdownExport`, `NotionImport`, `Sync`) зависят от ядра, ядро от них — нет (принцип V). Сервер — отдельная папка со своим менеджером пакетов.

## Этапы (вертикальные срезы)

| № | Этап | Зависит от | Можно параллельно с |
|---|------|------------|---------------------|
| 0 | Каркас: XcodeGen, пакет, пустое окно, генератор эталонной базы, первый замер запуска | — | — |
| 1 | US1: страница, абзацы, автосохранение, ошибка записи | 0 | — |
| 2 | US2: дерево, вложенность, перенос, корзина | 1 | 3 |
| 3 | US3: все типы блоков, оформление, «/», перестановка, отмена | 1 | 2 |
| 4 | US4: поиск страниц | 1 | 5, 7 |
| 5 | Выгрузка в Markdown | 2, 3 | 4, 7 |
| 6 | US6: импорт из Notion | 3, 5 (общий разбор Markdown) | 7 |
| 7 | Сервер синхронизации + развёртывание на `mynotion.kurilov.cloud` | 0 | 2–6 |
| 8 | US5: синхронизация в приложении, конфликты, подключение второго Mac | 2, 3, 7 | — |
| 9 | Полный прогон тестов и замеров, сборка для `/Applications` | все | — |

Работа идёт в ветке `001-core-pages-editor`; каждый этап предъявляется Юрию в сборке с результатами затронутых тестов и замеров (конституция, «Порядок работы»).

Синхронизация затрагивает модель записей, поэтому поля часов (HLC) закладываются в `NotesCore` уже в этапе 1, а не переделываются в этапе 8.

## Complexity Tracking

| Отступление | Зачем | Почему проще не подходит |
|-------------|-------|--------------------------|
| Второй проект (сервер) | Синхронизация через сервер Юрия — его решение | Без сервера Mac не увидят изменений друг друга, когда не в одной сети |
| Сторонняя библиотека GRDB | Миграции, наблюдение для нескольких окон, безопасные потоки над SQLite | Своя обёртка над C-интерфейсом — больше кода и рисков потери данных, чем 2 МБ библиотеки |
