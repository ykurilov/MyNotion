# Research: Управление MyNotion из командной строки

Карта кода снята 24.10.2026 с ветки 004 (3c35fe6). Пути: `PK/` = `Packages/MyNotionKit/`, `Src/` = `PK/Sources/`.

Что есть в коде и задаёт решения:

- Входа для команд нет совсем: ни схемы `mynotion://`, ни AppleScript, ни сокета, ни XPC. Есть только флаги запуска (`App/Launch/LaunchOptions.swift`), в том числе служебные `--export-markdown` и `--import-notion`.
- Единого фасада операций нет. `NotesStore` (`Src/NotesCore/Storage/NotesStore.swift`) — чтение и сырые транзакции, `Sendable`, работает с любого потока. Настоящие операции — в двух `@MainActor`-классах с необязательным `undoManager`: `PageTreeOperations` (страницы, корзина, иконка, обложка, избранное, шаблоны, копия, перенос блоков, восстановление версии) и `DatabaseOperations` (всё 004).
- Живая страница — `PageDocument` (`Src/NotesCore/Document/`, `@MainActor @Observable`), общая через `OpenDocuments`: окно и любой другой владелец получают один и тот же объект. Отмену регистрирует вид (`PageTextView.changeBlocks`), а не документ.
- Правила отступа и переноса блоков (`BlockMoveController.indenting`, `moving`, `subtreeEnd`) — чистые функции над `[Block]`, но внутренние и лежат в модуле с AppKit (`Src/PageEditor/`).
- Прямая запись `store.write` интерфейс не обновляет. Обновление после внешней правки уже есть у синхронизации: `PagesLibrary.remoteChangesApplied` → `reloadTree`, `DatabaseOperations.announce(nil)`, окна, `openDocuments.applyExternalChanges(toPages:)`.
- Любая запись через `NotesStore.write` в процессе приложения сама ставится в очередь синхронизации (`OutboxRecorder` + `Outbox.didEnqueue`).

## R1. Вход для команд — Unix-сокет в папке приложения

**Decision**: приложение слушает Unix-сокет `~/Library/Application Support/MyNotion/control.sock`. Обмен — строки JSON (один запрос — одна строка, ответ — строка или несколько строк хода и итоговая). Доступ:

- сокет создаётся с правами `0600` (под `umask 077` до `bind`);
- у каждого подключения проверяется владелец через `getpeereid`: чужой uid — закрыть без ответа (FR-401);
- сокет только локальный, сети нет.

Устаревший файл сокета (приложение упало): при запуске пробное подключение. Нет ответа — файл удаляется и создаётся заново. Есть ответ — работает другая копия приложения, эта сокет не трогает и пишет об этом в журнал.

Путь короче предела `sun_path` (104 байта): 64 байта у Юрия. При `--database <путь>` (тесты, эталон) сокет — рядом с базой, а если путь длиннее предела — `$TMPDIR/mynotion-<8 знаков хэша пути базы>.sock`. Клиенту путь передаётся флагом `--socket` или `MYNOTION_SOCKET`.

**Rationale**: ответ на каждый запрос, права проверяет ядро macOS, в покое ничего не делает — ждёт `accept` через `DispatchSource` (FR-405). Без новых зависимостей: Foundation и Darwin.

**Alternatives considered**:
- XPC-служба с именем (`NSXPCListener(machServiceName:)`) — имя регистрирует только launchd. Пришлось бы ставить LaunchAgent, и launchd сам поднимал бы приложение. Это лишняя служба в системе. Безымянный XPC клиент не найдёт.
- Apple Events / AppleScript — macOS спрашивает разрешение «Автоматизация» для каждой программы, откуда идёт команда (терминал, Codex, Paseo). Агенты в фоне на этом застрянут. Плюс словарь `.sdef` и медленный разбор.
- Локальный HTTP на `127.0.0.1` — до него достают все пользователи Mac и страницы браузера (подделка запросов, подмена имени). Нужен ключ и защита. Сокет с правами проще и надёжнее.
- Схема `mynotion://` и общие уведомления — без ответа, команда не узнает итог.
- Писать в SQLite из команды напрямую — отвергнуто Юрием (вариант 1): приложение не заметит записи, открытые страницы её затрут, синхронизация не проснётся.

## R2. Порядок выполнения

**Decision**: сервер читает сокеты в фоне, а каждый запрос выполняет `@MainActor CommandExecutor`. Команды делятся на чтение и запись (признак в каталоге команд):

- запись берёт общий асинхронный замок и идёт строго по одной (FR-404);
- чтение идёт без замка на снимке базы (`DatabasePool` читает только зафиксированное) и не ждёт долгую запись — импорт отдаёт главный поток между пачками;
- у долгих команд (импорт, выгрузка) ход идёт строками `{"progress":…}` до итога; разрыв связи клиентом команду не прерывает (начатое доводится до конца, как импорт из меню).

**Rationale**: модели приложения живут на главном потоке. Выполнять там же — значит пользоваться ими как интерфейс, без новых правил одновременности.

## R3. Путь правки агента — тот же, что у интерфейса

**Decision**: модуль команд работает только через существующие операции, ни одного «своего» SQL записи:

- страницы, иконки, обложки, избранное, шаблоны, корзина — свой экземпляр `PageTreeOperations(store:undoManager:)` с колбэками, которые приложение подключает к `PagesLibrary.treeDidChange` (как у окна);
- блоки — через `OpenDocuments.open(pageId)` → `PageDocument.replaceBlocks / setText / setTitle / apply`, затем `release`. Если страница открыта в окне, это тот же объект: окно обновляется сразу, а незаписанный ввод Юрия уже лежит в документе (Q2 решается сам). После правки документ сохраняется сразу, до ответа: «успех» значит «записано на диск» (конституция IV);
- базы — свой экземпляр `DatabaseOperations` и `DatabaseOperations.announce`;
- после правки, которая меняет страницы, не открытые этим путём (Markdown целиком, импорт), — тот же шаг, что после синхронизации: `openDocuments.applyExternalChanges(toPages:)` и обновление окон.

Отмена: операции получают свой `UndoManager` команды, не связанный с окнами (Q1). Он нужен только для отката пакета (R6) и выбрасывается после команды.

**Rationale**: открытые окна, поиск, обратные ссылки, формулы, выгрузка и синхронизация уже подписаны на эти пути (FR-403). Любой «короткий путь» мимо операций — риск потерять правку или синхронизацию.

## R4. Правила отступа и переноса блоков — в модуль без окна

**Decision**: чистые функции `indenting`, `moving`, `movedGroup`, `subtreeEnd`, `headingIndent` переезжают из `Src/PageEditor/BlockMoveController.swift` в `Src/NotesCore/Document/BlockStructure.swift` (публичные). `BlockMoveController` остаётся для окна (зазор под указателем) и вызывает их. Отметка задачи, раскрытие, смена вида — правка полей блока через `PageDocument.apply` (как `toggleCheckbox` окна). Тесты окна на эти правила переносятся вместе с функциями, без изменения.

**Rationale**: одно правило для окна и агента. Копия правил разошлась бы при первой правке.

## R5. Markdown: чтение — выгрузка, запись — разбор импорта Notion

**Decision**: новый модуль `PageMarkdown` с двумя функциями:

- `markdown(ofPage:)` — `MarkdownBlockWriter` выгрузки, как файл выгрузки без шапки-файла (FR-413, SC-404);
- `blocks(fromMarkdown:)` — `NotionMarkdownParser().parse` и перевод `ParsedBlock → BlockDraft`. Этот перевод сейчас закрыт внутри `NotionImporter.blocks(for:in:...)` (`NotionImporter.swift:~424`). Он выносится в публичный `ParsedBlockConverter` в модуле `NotionImport`, импорт Notion переходит на него без изменений поведения.

Разбор Notion — это обычный CommonMark с таблицами GFM, задачами, `<u>`, выносками и раскрывающимися списками в виде, который пишет выгрузка MyNotion. Поэтому для агента он подходит как есть. Особые правила Notion отключаются флагом разбора `.plainMarkdown`:

- первая строка `# Заголовок` не становится названием страницы;
- ссылки на соседние `.md` не ищутся в папке выгрузки;
- картинки по локальному пути — вложения через `AttachmentStore.importFile`, по `http(s)` — блок-картинка со ссылкой.

Неподдержанное (HTML-блоки, сноски) уходит в текст абзаца, и в `warnings` добавляется номер строки (FR-414).

**Rationale**: выгрузка и разбор уже зеркальны (002, 004), round-trip тестами выгрузки → импорта проверен. Свой третий разборщик — лишний код и расхождения.

**Alternatives considered**: `swift-markdown` (Apple) — новая зависимость с cmark-gfm. Даёт только дерево Markdown, без перевода в блоки MyNotion. Перевод всё равно пришлось бы писать, а зеркальность с выгрузкой терялась бы.

## R6. Пакет `batch` — откат через свою отмену

**Decision**: шаги пакета выполняются по очереди под одним замком записи с общим `UndoManager` команды (R3). При ошибке шага все зарегистрированные отмены выполняются в обратном порядке, и приходит ответ `batch_failed` с номером шага и его ошибкой. Команды без отмены в пакет не принимаются: проверка до выполнения, код `not_batchable`. Это окончательное удаление, очистка корзины, импорт, выгрузка, восстановление версии, `sync now` и команды окна. Ссылка на результат прошлого шага — `"$1.id"` (результат шага 1).

**Rationale**: операции 001–004 уже умеют точную отмену, проверенную тестами ⌘Z. Одна транзакция на весь пакет невозможна: каждая операция открывает свою.

**Alternatives considered**: снимок страниц до пакета и откат по снимку — не покрывает базы, избранное и корзину целиком.

## R7. Версия «до правки агента»

**Decision**: перед первой записью в страницу `AgentEditCheckpoint` смотрит, есть ли у неё версия с отметкой агента моложе 10 минут. Если нет — снимает версию тем же `PageVersionRecorder`, что и обычные версии. Отметка — поле `agent: String?` в `VersionSummary`: это JSON в колонке `summary`, миграции нет. Такие версии прореживание сохраняет наравне с `isBeforeRestore`: `VersionStamp` получает признак из `summary`. В окне истории подпись — «до правки агента (имя)». Для строки базы снимок включает ячейки (версия 2 снимка 004).

**Rationale**: возврат всего, что сделал агент, — одной кнопкой «Восстановить» (SC-407). Изменения схемы базы нет, значит нет миграции и риска для данных.

## R8. Консольная команда — тонкий клиент внутри приложения

**Decision**: новая цель `mynotion` (тип `tool`, Swift, без AppKit) в `project.yml`. Она кладётся в пакет приложения: `MyNotion.app/Contents/Helpers/mynotion`. Установка делает ссылку `~/.local/bin/mynotion` → этот файл, поэтому команда всегда той же версии, что приложение (FR-429). Клиент:

1. разбирает аргументы по каталогу команд (R9), выдаёт `--help` без запуска приложения;
2. подключается к сокету;
3. если сокета нет и не задан `--no-launch` — запускает своё приложение (путь пакета берётся из собственного пути после разыменования ссылки) командой `open -g <пакет>` (без захвата фокуса), затем каждые 100 мс пробует подключиться, до `--launch-timeout` (15 с);
4. шлёт запрос с версией протокола и печатает ответ: JSON как есть или кратко (`--human`). Код выхода берётся по группе ошибки (contracts/protocol.md).

**Rationale**: агенту нужен один исполняемый файл в `PATH`. Своя логика клиента — только разбор аргументов и запуск, всё остальное выполняет приложение.

## R9. Каталог команд — один на клиент и приложение

**Decision**: модуль `ControlProtocol` (без зависимостей, кроме Foundation) содержит:

- запрос, ответ и ошибку — `Codable`;
- закрытый список кодов ошибок;
- каталог всех команд: группа, действие, аргументы с типами, флаги, чтение или запись, можно ли в пакет, справка, пример;
- разбор аргументов по каталогу.

Клиент по каталогу печатает `--help` и `commands --json`, приложение по нему проверяет запрос. Каталог описан целиком на первом этапе (contracts/commands.md). Обработчики групп появляются по этапам; до своего этапа команда отвечает `not_implemented`.

**Rationale**: справка и проверка из одного места не расходятся. Первый этап закрепляет весь протокол, и параллельные этапы его не правят.

**Alternatives considered**: `swift-argument-parser` — новая зависимость ради разбора, который по каталогу занимает ≈ 200 строк. Плюс второе описание команд рядом с каталогом.

## R10. Указатель страницы

**Decision**: `PageLocator` разбирает:

- id (UUID, регистр не важен, допустим префикс от 8 знаков, если он однозначен);
- `current` — страница передней вкладки переднего окна (`PagesLibrary.activeWindow`);
- путь из названий через `/` (сравнение без учёта регистра и `ё/е`; `\/` — косая черта внутри названия).

Неоднозначность — `ambiguous_page` с кандидатами. Страницы в корзине видны только с `--include-trashed`. Строка базы — та же страница. Блок — только id, строкой из `page read --format json`.

## R11. Журнал команд

**Decision**: `os.Logger(subsystem: "cloud.kurilov.mynotion", category: "control")`, одна строка на команду: имя, указатель, итог или код ошибки, длительность, имя агента. Текст записей в журнал не пишется (FR-432). Смотреть: `log show --predicate 'category == "control"'` — это есть в скилле.

## R12. Окно и вкладки

**Decision**: `WindowControl` — протокол в модуле команд. Его реализует приложение (`App/Control/AppWindowControl.swift`) поверх `MainWindowModel` (`open(PageOpenRequest)`, `goBack`, `goForward`, `openInNewTab`) и `WindowTabs`. Новое окно — через `openWindow(id:)` сцены (как ⌘N). Без `--activate` окна не выходят вперёд (`orderFront` без `activate`); с ним — `NSApp.activate`. В тестах модуля — подставной `WindowControl`. Если у окна открыт лист (импорт, настройки) — ответ `window_busy`.

## R13. Запуск: сокет — после готовности библиотеки

**Decision**: сервер стартует в конце `openLibrary`, когда хранилище открыто, переходы базы и откат прерванного импорта завершены. Если запуск идёт через окно восстановления после сбоя, сервер ждёт его закрытия, а клиент — до своего срока, затем `app_not_ready`. Создание сокета — это `socket`, `bind`, `listen` и один `DispatchSource`: десятки микросекунд, после готовности редактора. Холодный запуск не меняется (SC-406, замер в этапе 1).

## R14. Скилл и установка

**Decision**: исходник скилла лежит в репозитории: `Tools/mynotion-skill/SKILL.md` и `references/<группа>.md` — у каждой группы команд свой файл, его пишет этап группы. Установка `scripts/install-cli.sh`:

1. копирует Release-сборку в `/Applications`, если приложение не запущено; иначе — просит закрыть его и выходит без изменений;
2. делает ссылку `~/.local/bin/mynotion`;
3. копирует скилл в `~/.agents/skills/mynotion` (настоящей папкой, как соседние скиллы);
4. запускает `skill-doctor.sh` на эту папку.

Claude и Claude 2 видят скилл через ссылки `~/.claude/skills → ~/.agents/skills` и `~/.claude-second/skills → ~/.claude/skills`. Codex читает `~/.agents/skills` сам. Установка проверяет: если у Codex скилла не видно, делает ссылку `~/.codex/skills/mynotion`.

Замена `/Applications/MyNotion.app` на основном Mac — рабочее приложение Юрия. Её делает главный агент последним шагом только с согласия Юрия; до этого всё проверяется на iMac.

## R15. Проверки

- Модули `ControlProtocol`, `ControlCommands`, `ControlServer`, `PageMarkdown` — Swift Testing на iMac (`imac-run … swift test --jobs 4`), без окна. `ControlCommands` проверяется на временной базе с настоящими `PageTreeOperations` и `DatabaseOperations` и подставным `WindowControl`.
- Сервер — тест на временном сокете: права, чужой uid (подставная проверка), порядок, разрыв связи.
- Клиент — тест разбора аргументов и запуска с подставным «запускателем».
- Сквозной сценарий — один (quickstart.md, сценарий A): на iMac Release-сборка, приложение закрыто, скрипт `scripts/imac/cli-e2e.zsh` вызывает команды US1–US5 и сверяет JSON; окно снимается CuaDriver для проверки «окно обновилось». Полный прогон всех тестов — один раз в конце.
- Замеры: запуск и память в покое с сокетом (SC-406), время ответа (SC-402) — в конце этапа 1 и в конце фичи.
